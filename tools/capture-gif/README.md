# 패치노트용 GIF 캡처

배포된 룰렛을 헤드리스 크롬으로 열어 **당첨 순간(폭죽 + 색종이)** 을 GIF로 만든다.
게시판에 올릴 패치노트 첨부용.

```bash
cd tools/capture-gif
npm install
npx playwright install chromium   # 최초 1회 (~130MB)
node capture.mjs celebration.gif
```

- 화면 전체(1280×1000 뷰포트)를 760×594로 담고, 당첨 직전 0.3초부터 2.2초를 캡처한다.
- 용량 목표는 **9MB**(네이버 카페 1장 10MB 제한 대비 여유). 색상 수 → 프레임 간격 순으로
  자동 조절해 목표 안에 맞춘다. 콘솔에 시도 내역이 찍힌다.
- 후보 메뉴는 스크립트 상단 `MENUS`에 들어 있다(도네로 만들어진 것처럼 추천자 닉네임 포함).
  배포본에는 디버그 훅이 없어 `localStorage`에 직접 심는 방식이다.
- `sample-0/1/2.png` 로 당첨 후 0.15·0.45·0.9초 시점 프레임이 함께 저장된다(확인용).

> 결과 GIF는 용량이 커서 저장소에 커밋하지 않는다(`.gitignore`). 필요할 때 다시 뽑아 쓴다.

## 화면 배치 측정 (measure.mjs · phase.mjs)

`npm run dev`를 띄운 뒤 `node measure.mjs` — 1920×920/1080/1120 창에서 후보가 몇 줄 보이는지, 룰렛 크기,
페이지 스크롤, 좌우 여백을 잰다. `node phase.mjs` — 모집·당첨 발표·리롤 접수 단계마다 룰렛 칸 안에 버튼까지
다 들어가는지(넘침 px) 잰다. 레이아웃을 손볼 때 전후를 숫자로 비교하는 용도.

## 공지 움짤 (patch-gifs.mjs)

`npm run dev`를 띄운 뒤 `node patch-gifs.mjs` — `docs/patch-2026-11-01.gif` **한 장**.
실제 방송 화면 그대로 **1920×1080**(1920×1080 모니터에서 [전체화면]을 켠 크기), 도네 피드를 미리 채운 채로
메뉴 → 룰렛 → 리롤 장면을 한 번에 찍고 `cuts`에 적은 구간만 이어 붙인다(감속 앞부분·색종이 가라앉는 시간은 잘라 냄).
다음 공지 때는 장면 블록만 바꿔 쓴다.

녹화·인코딩은 `gif.mjs`(capture.mjs와 공용). 프레임마다 **앞 프레임과 같은 픽셀은 투명**으로 남겨 바뀐 곳만 담고,
그래도 9MB를 넘으면 색 수 → 프레임 간격(초당 50 → 10장) 순으로 줄인다. 룰렛이 도는 장면이 가장 무겁다
(17초에 96색 · 초당 9장 정도). 찍은 뒤에는 꼭 GIF를 다시 풀어 장면이 의도대로인지 본다.
